# 产品需求文档（PRD）

> **定位**：omnimd 的产品规格——做什么、不做什么、产出长什么样、怎么算验收合格。实现原理见 [architecture.md](architecture.md)。
> **读者**：使用者、维护者
> **最后更新**：2026-10-11

---

## 一、产品定位与边界

### 1.1 是什么

omnimd 是一个通用的文件转 Markdown 工具（CLI 与 Python 库两种使用面）：把文档与图片转换为「正文 + 图片链接 + 图片转写文本」三合一的 Markdown，产出的文本直接可被 LLM / coding agent / 知识库消费。文件解析是所有 LLM 工作流的第一公里，本工具就是这一公里。

产品愿景是「任意文件 → LLM 可用的 Markdown」：文档与图片已支持，音频、视频转写在规划中（[ROADMAP](../ROADMAP.md)）。

### 1.2 不是什么

- **不做排版美化**——是解析工具，追求无损与可检索，不追求还原视觉排版
- **不是 OCR 服务**——图片转写是管线的内部环节，不单独对外提供接口
- **不做 GUI**——CLI 与 Python 库是核心使用面（Web 演示 [demo/](../demo) 与 Claude Code skill [skills/omnimd/](../skills/omnimd) 是基于库的演示/集成形态，不是独立产品）
- **不做内容加工**——源文档内容逐字保留，不纠错、不润色、不翻译

### 1.3 产品红线

1. **无损**：除装饰性小图外，源文档的任何信息不得丢弃（违者即缺陷）
2. **密钥不落文档**：配置唯一来源是 .env，文档与代码示例不出现真实密钥
3. **缺配置即失败**：宁可启动报错，不做静默回退

## 二、用户与使用方式

| 用户 | 场景 |
|---|---|
| 开发者（与 coding agent 协作） | 把需求文档/产品手册/方案 PDF 转成 Markdown，作为 agent 的上下文喂入 |
| 知识库构建者 | 批量转换文档进 RAG 管线；文档更新后重跑 |
| 维护者/Agent | 新增解析引擎、切换 VLM 端点或存储后端；排查转换异常 |

**CLI 入口**：

```bash
omnimd <文件或目录...> [-o 输出目录] [--output url,text] [--concurrency N] [--cache-dir 目录] [-v]
```

**Python 库入口**（安装后在自己的代码里调用）：

```python
from omnimd import OmniMD

md = OmniMD()                            # 读环境变量 / .env 构造
result = md.convert("报告.pdf", output="url")   # → ConversionResult（.markdown 为产出全文）
```

配置与转换分离：连接配置在构造时配齐（环境变量或显式参数对象），
`convert()` 只传文件与本次产出组成。两种入口共用同一套配置加载与转换管线。

## 三、功能清单

### 3.1 输入

| 功能 | 说明 |
|---|---|
| 单文件转换 | 任意受支持格式（文档或图片） |
| 目录批处理 | 目录下所有文件按名排序转换；不支持的格式**一次报全** |
| 文档格式 | `.pdf .docx .docm .doc .odt .ods .odp .ppt .pptx .pptm .ppsx .ppsm .rtf .epub .xlsx .xlsm .xlsb .xls .csv .html .htm .json .xml .zip .txt .md .rst .ipynb` |
| 图片输入 | `.png .jpg .jpeg .gif .bmp .webp .tif .tiff .svg .ico`——单张图片直接作为输入，产出同文档内嵌图片一致的「链接 + 转写文本」 |

### 3.2 解析引擎（非 PDF 格式）

| 功能 | 说明 |
|---|---|
| 引擎选择 | `DOC_ENGINE` 配置：`markitdown`（缺省，支持的格式最多）/ `anydoc`（正文质量优先——合并单元格/公式/脚注保真更好） |
| 格式回退 | 所选引擎不支持的格式自动回退另一引擎，支持的格式取并集 |
| PDF 固定路线 | PDF 不受 DOC_ENGINE 影响，固定走 pymupdf4llm——两候选引擎的 PDF 转换都丢失全部内嵌图片，没有选择余地 |

### 3.3 图片处理

| 功能 | 说明 |
|---|---|
| 产出组成 | 每次转换可选（`url` / `text` / `alt` 逗号分隔多选，`alt` 依赖 `url`）：`url` 保留图片公开链接；`text` 附加转写文本；`alt` 生成链接的描述文本（`text`/`alt` 需调用视觉模型，产生调用成本）；未设置时取 `url,text` |
| 装饰图过滤 | 短边 < 60px 的图标/分隔线直接丢弃，不产生占位符 |
| 内容去重 | 相同图片（SHA-256 相同）只上传、转写一次，多处引用同一 URL |
| 图片托管 | 上传至配置的存储后端换取长期公开 URL |
| 图片转写 | 视觉模型把图片转为结构化 Markdown 文本——提取确定性内容（文字/数值/表格/结构）+ 描述视觉现象（布局/印章/场景）；无法辨认的内容显式标注 `[?]`，不猜测。提示词正文见 [prompts/](../omnimd/prompts) |

### 3.4 缓存与成本

| 功能 | 说明 |
|---|---|
| 转写缓存 | 转写结果持久化；同一 VLM 下重跑不再调用模型 |
| URL 缓存 | 上传结果持久化；同一存储（端点与桶）下重跑不再上传 |
| 隔离切换 | 缓存按思考控制方式/模型隔离——换模型或换思考控制方式强制重新转写（便于评估新模型），换存储强制重新上传 |

### 3.5 端点与引擎切换

| 维度 | 可选值 | 切换方式 |
|---|---|---|
| VLM | 任意 OpenAI 兼容端点（凭据三项 KEY/URL/MODEL 直接接入） | 改 .env 的凭据三项；VLM_THINKING 选思考控制方式（none 缺省 / thinking-off|on / template-off|on / effort-off|on / both-off|on） |
| 存储 | s3（S3 兼容通用项：自托管 MinIO / OBS / OSS / COS 等） | 改 .env 的 STORAGE_PROVIDER + 对应凭据 |

## 四、产出规格（下游消费契约）

> 本节是下游消费方（coding agent、知识库、检索系统）依赖的**稳定契约**，改动即破坏兼容。

### 4.1 输出文件

- 命名：`{输入文件名去扩展名}.md`；同批同名冲突自动加序号（`a.md` → `a-1.md`）
- 语义：重跑同名文件覆盖刷新（适配文件版本迭代）
- 编码：UTF-8

### 4.2 图片块形态

产出组成决定每张图片的渲染：`url` 渲染图片链接，`text` 在链接下方附完整转写文本块，`alt` 把一句话描述写进链接的描述位（alt 位，依赖 url）。全选时：

```markdown
![图片的一句话描述](https://<存储域名>/<桶名>/<前缀><sha256>.png)
{视觉模型输出的完整 Markdown 文本}
```

- 图片 URL 长期有效、匿名可访问、无过期时间
- 转写失败的图片：URL 正常输出，文本位置写「（图片转写失败）」，不中断整批
- 装饰性图片：整个图片块消失，不留占位

## 五、配置体验

- **连接配置只认 .env**：VLM 与存储的全部连接配置只认 .env / 环境变量——CLI 不提供凭据传参；Python 库可显式传连接配置（覆盖环境值）
- **凭据无默认值**：凭据变量（KEY/URL/MODEL）缺失时报错并列出全部缺失项；存储按需必填——产出组成含图片链接、或转写走 URL 传图（缺省）时才要求存储；`VLM_IMAGE_INPUT=base64` 时纯转写可不配存储运行
- **端点切换整体一致**：凭据三项（key/url/model）随端点整体更换，CLI 不提供单独覆盖凭据的参数；VLM_THINKING 是思考控制方式（缺省 none 不发参数），不是凭据

配置项速查见 [.env.example](../.env.example)，完整说明见根 [README.md](../README.md)。

## 六、验收标准

| # | 标准 | 判定方式 |
|---|---|---|
| 1 | 每张非装饰图片 = 可显示链接 + 转写文本（缺省产出组成 `url,text`） | 抽查产出 Markdown |
| 2 | 全批转换 0 图片转写失败 | 检索「（图片转写失败）」为零 |
| 3 | 图片 URL 匿名 GET 返回 200 | 浏览器无痕窗口打开抽查 |
| 4 | 重跑同一文档，API 调用次数为 0 | `-v` 调试日志中无 HTTP 请求记录 |
| 5 | 缺任一必填配置，启动报错且列出缺失项 | 删变量后运行 |
| 6 | 换模型或换存储（端点/桶）后，全流程正常且缓存按新配置重新生成 | 改 .env 后跑通 |
| 7 | DOC_ENGINE 两种取值下全流程正常，格式回退生效 | 用 .doc 与 .html 各验证一次 |
